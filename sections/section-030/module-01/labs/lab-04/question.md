# Question

Solve this question on: `terminal`

Kyverno is ready without policies. New application namespaces need a NetworkPolicy generated by the background controller.

## Tasks

1. Write a ClusterPolicy that matches new Namespace objects and generates `default-deny` in that namespace.

2. The generated NetworkPolicy must select all Pods with an empty `podSelector` and list both `Ingress` and `Egress`, without allow rules. Exclude `kube-system`, `kube-public`, `kube-node-lease`, `kyverno` and `local-path-storage`.

3. Create a temporary application namespace and inspect its generated policy. Set `synchronize: true` and prove Kyverno recreates the policy after deletion. Remove the temporary namespace after checking it.

Keep the prepared workloads, service accounts and namespace labels unchanged.

This task proves policy generation. The cluster network plugin does not enforce NetworkPolicy, so this lab does not grade packet filtering.

Learner work: about 15 minutes. Cluster startup and controller reconciliation take additional time.
